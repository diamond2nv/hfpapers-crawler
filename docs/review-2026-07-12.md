## 二、P0 Bug — `_title_similarity` 静默失效

### 位置
`hfpapers/paper_store.py:834`

### 代码
```python
from hfpapers.evolved import HFPapersCrawler
sim = HFPapersCrawler._title_similarity(title, r["title"])
```

### 问题
`_title_similarity` 在 v0.5.x 重构中从 `HFPapersCrawler` **移到了** `search_queue._title_similarity`（独立函数，非类方法）。结果是：
- `HFPapersCrawler._title_similarity` → `AttributeError`
- `cross_verify()` 每次调用都抛出异常 → **catch 后静默吞掉**
- 所有论文的 Crossref 验证 **从未真正成功匹配过标题**
- 这是 `verified=0`（即使有 DOI）的根本原因

### 修复
```python
from hfpapers.search_queue import _title_similarity
sim = _title_similarity(title, r["title"])
```

## 三、Cross-Referencing Issue — paper_store ↔ audit 两套相似度代码

| 文件 | 函数 | 算法 |
|:-----|:------|:------|
| `search_queue.py:423` | `_title_similarity()` | Trigram Jaccard |
| `_text_similarity.py` | `title_similarity()` | TF-IDF + Cosine + fuzzy |
| `audit/similarity.py` | 包装 | 包装 `_text_similarity` |

**问题**:
1. `paper_store.py:834` 用 Trigram Jaccard（简单但精度有限）
2. `citation_audit_oa.py` / `citation_audit_s2.py` 用 TF-IDF（更精确）
3. 两套相似度算法各自独立演进，无统一入口

**建议**: 统一到 `_text_similarity.py`，让 `search_queue._title_similarity` 也调用它。

## 四、代码健康问题

### 4.1 测试覆盖率衰退

| 组件 | 测试文件数 | 备注 |
|:-----|:----------|:------|
| paper_store | 1 (`test_paper_store.py`) | 基础 CRUD ✅ |
| verify 管线 | 2 (`test_verify_*.py`) | ✅ |
| audit | 3 (`test_audit.py`, `test_citation_audit_*.py`) | ✅ |
| evolved/cli | 2 | ✅ |
| **paper_store.cross_verify** | **0** | ❌ **无测试** — 所以标题相似度 bug 未被检出 |

**建议**: 为 `cross_verify()` 加单元测试（mock Crossref API）。

### 4.2 `media/` 目录污染

`media/` 含 80+ 自动生成的 SVG/MP4/Tex 文件（Manim 动画输出），未被 `.gitignore` 排除。`git add -A` 时会意外追踪大文件。

**建议**: `.gitignore` 加 `media/`。

### 4.3 `cross_verify` 无 rate limit 保护

`CrossrefClient.cross_verify()` 内部调用 `title_to_doi()`（循环多条结果），但无显式 rate limiting。超过 1 req/s 会被 Crossref API 封。

**建议**: 加 `time.sleep(1.1)` 或使用 `requests` 适配器的连接池。

### 4.4 `arxiv-live-to-hfpclawer.py` 不在仓库中

桥接脚本在 `~/.hermes/scripts/` 而非仓库内，版本与 hfpclawer 解耦。容易不同步。

**建议**: 软链或移入 `scripts/` 目录。

### 4.5 import 循环引用

`paper_store.py:959`:
```python
from hfpapers.evolved import HFPapersCrawler  # Inside function to avoid circular
```
同类方法做了一次但 `_title_similarity` 已不在此类中。修复 §2 后可以去掉这个循环 import hack。

## 五、功能缺口

### 5.1 Paper Store 缺少检索命令

```bash
# 当前
hfpclawer store stats                              # ✅
hfpclawer store export --format json|csv           # ✅

# 缺失
hfpclawer store search --keyword "optomechanics"   # ❌
hfpclawer store search --source "cron:coc"         # ❌
hfpclawer store list --unverified                  # ❌
```

这几个 CLI 子命令对日常使用非常必要。

### 5.2 批量重验证缺少 CLI

`scripts/hfpclawer-audit-verify.py` 是独立脚本，不是 `hfpclawer verify` 子命令。

**建议**: 注册为 `hfpclawer verify cron` 或 `hfpclawer store verify --deferred`。

### 5.3 arXiv 撤回检测不完善

当前只检查 title 前缀 `WITHDRAWN`。arXiv 的撤回标记还可能有：
- `<arxiv:withdrawn>` 元素
- 版本标签 `v2` 替换版本
- `announce_type` 字段

## 六、PyPI 发布风险

| 问题 | 详情 |
|:-----|:------|
| `arxiv extra` 锁 git dep | `pyproject.toml` 中 `arxiv-metadata-service` 依赖 GitHub tag，PyPI 不允许多次 |
| 无 PyPI 自动发布 CI | 当前手动 `twine upload` |
| `pyproject.toml` 与 `__init__.py` 版本重复 | 两处都需要改，容易不同步 |
| 长期未发布 | v0.8.1 未发布到 PyPI（上一版是 v0.4.x） |

**建议**: 
- `pip install hfpclawer` 时用 `@v0.2.0` 兼容格式
- 加 GitHub Actions release workflow
- `__version__` 从 `importlib.metadata` 读取（已有 v0.5.x 的 setup，但没用）

## 八、总结

**hfpapers-crawler 是功能完备的工具链**（61 commits, 22 test files, 4 audit 引擎），但：
1. **`_title_similarity` 静默失效** 是唯一值得紧急修复的问题 — 它让所有 arXiv→Crossref 的交叉验证返回空但无声无息
2. **版本标签缺失** 让问题难以追溯
3. **其余是工程质量提升** — 测试覆盖率、CLI 补全、gitignore、代码统一
